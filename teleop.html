Stereo passthrough

The head ZED's left/right streams map onto an inward-facing RealityKit sphere — you look around the robot's world in true stereo, with wrist-cam thumbnails for close work.

A UMI-style relative mapping: pinch to clutch in, move, release to re-anchor — no jumps. Thumb-to-index distance becomes the grasp. See retargeting.

Additional · Mac-side setup

Run the bridge, reach it anywhere.

All three clients connect to one process — server/sim_teleop_bridge.py on a Mac — which drives the MuJoCo twin or the real robot and serves the cameras. You only need this to go past the in-browser sim. One command, three networks.

01
One command

server/start_teleop.sh brings up physics + cameras. Intent arrives on ws://<host>:9090 as a teleop_frame; the cameras leave as plain MJPEG over HTTP on :8080, kept off the control socket.

02
Three ways in

Wi-Fi (Bonjour auto-discovery, lowest latency) → VPN (the Mac's Tailscale IP / ts.net name, any network) → Relay (token-gated public VPS). Each client just tries them in order — no mode switch.

03
Secure by construction

For the public path the robot dials out to the relay; Caddy enforces TLS + a ?key= token (403 without it). Nothing is exposed inbound. Full architecture, security model, and the live monitor → Software · Server & bridge.

Built for data

Every session is a dataset.

A

Capture by default

Head + wrist cameras, joint states, actions, and the goal frame stream to disk in lockstep — one schema shared by sim and real.

B

Intent in, motion out

Your hand and gaze become a 6-DOF target; the control cascade works out how 51 joints honor it — safely.

C

Demos become skills

Logged trajectories train Diffusion Policy and ACT — the same interfaces that drive the robot feed the learning loop.
