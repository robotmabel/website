Teleop · Browser

Teleop it. Right here.

The same cockpit as the iPhone app, rebuilt for the web. Drive the base and arms with joysticks, switch the controller between firm (wrist / joint) and soft (gravity comp / compliance) modes, and watch every robot event in a live status console. Out of the box it runs an in-browser sim; press Connect to point it at a real MuJoCo bridge — then the 3D model mirrors the server's simulation state, frame for frame.

No server? Everything below still works on the in-browser sim. To drive the real MuJoCo twin, start the bridge from the MABEL repo (sim_teleop_bridge.py — see Server & Bridge), then connect to ws://<your-mac>:9090/teleop. Same eight-message protocol as the Vision Pro and iPhone apps; once connected, the incoming robot_state stream is the single source of truth for the 3D model.

The cockpit, in a tab.

02 · Robot control

Firm, or soft.

The Body-tab controls from the iPhone app. Firm modes command the robot — drag a wrist in Cartesian space or set joints directly. Soft modes let you push it around — gravity-compensated arms, and a compliant base that glides under a sustained shove.

Stiffness85 %

Drag a rust palm handle — the arm tracks the Cartesian wrist target stiffly. Lower the stiffness and the same drag turns sluggish and compliant.

Sliders set joint targets; the robot slews to them rate-limited — watch it move, don't teleport it.

Gravity comp: the arms are weightless and back-drivable. Drag a handle — it floats, and stays where you let go. No spring.

Compliance: keep pushing past the comfort box and the whole base admits the wrench — it glides with you and coasts to rest, the virtual mass-damper of admittance.py.

One canonical robot state drives both viewers — pose it here, scroll up, and the cockpit shows the same robot. Connected, mode switches go up as control_mode and slider moves as joint_command; the model itself only ever follows the server's robot_state.
