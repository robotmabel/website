Overview / Software / Firmware
L1 · Firmware

Our firmware, not theirs.

MABEL mixes actuators from five vendors — and each ships its own closed Windows tool to flash, tune, and ID them. We replace as much of that as we can with one modular firmware stack and one cross-platform GUI. Change a register, reassign a motor ID, read live status, jog a joint — all from the same app, on macOS or Ubuntu.

One GUI · all actuatorsmacOS + UbuntuREV CAN · reverse-engineeredDamiao · Feetech · DynamixelModular by limb
The idea

Off the vendor tools.

Every actuator company hands you a proprietary GUI — REV's Hardware Client, the Feetech debugger, Damiao's assistant, Dynamixel Wizard — usually Windows-only, each its own silo. We pulled the parts we need into our own code so the whole robot speaks one language.

01
Modular — one target per limb

Firmware lives in firmware/, one folder per actuated subsystem: swerve_drive, openarm (arms + body), orca_hand, head, lift. Any board can be flashed, debugged, or swapped without touching the rest.

02
Own the protocol

Wherever a vendor hides setup behind a closed app, we re-implement it natively — most dramatically the REV SPARK CAN stack, reverse-engineered end-to-end (below). No proprietary runtime sits between us and a motor.

03
Cross-platform on purpose

The GUI and host libraries run on macOS and Ubuntu — the two machines we actually develop and deploy on. Windows isn't tested yet. No vendor binary, no OS lock-in.

04
Always-usable

If the bus is down or the driver isn't built, the GUI opens in SIM mode with simulated telemetry and a badge — so you can lay out and test the interface with zero hardware.

Control Studio

One app for every actuator.

A shared iOS-styled GUI — same dark palette, type, vector sliders and pill toggles across the hand, swerve, and lift apps. Configure, monitor, and drive any joint from it.

A

Reassign IDs

Give a fresh ORCA-hand Feetech servo its ID, or change a Damiao motor's CAN ID, straight from the GUI — no vendor tool, no Windows machine.

B

Write registers

Edit the control registers directly — Feetech servo registers, REV SPARK parameters (control mode, idle brake, PID, encoder zero), Damiao limits and modes.

C

Live status

A telemetry sidebar streams position, velocity, current (load proxy) and temperature for every controller, colour-coded as values approach their limits.

D

Quick control

iOS toggle + slider per joint: jog a steering axis to an absolute angle, throttle a drive wheel, enable/disable a motor, fire an E-STOP — instantly.

E

Bus bring-up

The CAN-Bus panel brings the interface up / restarts / scans / doctors it, with a live link-and-bitrate strip and a streaming console — no terminal required.

F

Diagnostics

Sine-sweep a motor, zero an encoder, clear faults, read limits — the bring-up and test routines that used to need a vendor app are built in.

Swerve drive · the deep cut

Reverse-engineering REV SPARK.

The base runs REV SPARK controllers on a 3-module delta swerve. REV only exposes them through their Hardware Client and vendor libraries — so we read the sparkcan source, documented the wire protocol, and re-implemented it raw in Python (SocketCAN) and C++ (Teensy FlexCAN_T4). Zero dependency on REV's stack.

29-bit extended arbitration ID
arbId = (0x02 << 24)        // DEVICE_TYPE  = motor controller
      | (0x05 << 16)        // MANUFACTURER = REV Robotics
      | (apiClass << 10)
      | (apiIndex << 6)
      |  deviceId           // 1,3,5 = drive · 2,4,6 = steer
01
Control frames

Velocity (RPM), Position (rotations) and DutyCycle [-1,1] all share one 8-byte payload: an IEEE-754 little-endian float in bytes 0–3, zero-padded. Heartbeat, ClearFaults and BurnFlash are their own API classes.

02
The parameter system

Registers live under API class 48 with a per-write type tag (UINT / FLOAT / BOOL). That's how we set kCtrlType, kIdleMode, kInverted, the PID gain kP_0, and the steering kDutyCycleZeroOffset — the absolute-encoder zero.

03
Telemetry frames

Controllers broadcast periodic status: Period 0 (duty / voltage / current / temperature), Period 2 (encoder velocity + position), and Period 5 (absolute steering encoder, 0–1 rev) — which only streams once you flip kForceEnableStatus5.

04
One socket, cached

A single RX thread reads the bus non-blocking, masks the device ID out of each arbitration ID (can_id & 0x3F), and caches the latest value per motor behind a mutex — so a GetVelocity() call is a free cache read, not a bus round-trip.

The full mapping — every arb-ID, payload layout, and parameter table — lives in firmware/swerve_drive/rev_can_protocol.md, enough to write a clean-room driver from scratch.

The fleet

Every actuator, owned.

01

Swerve base · REV SPARK

NEO / NEO550 brushless on 3 delta modules. Reverse-engineered SPARK CAN in Python + Teensy C++; a drive sim and the Swerve Studio GUI on top.

02

Arms · Damiao DM

OpenArm-derived 7-DOF arms on quasi-direct-drive Damiao motors over CAN (Teensy + FlexCAN_T4). MIT-mode control with scanner, ID-change, mode-switch, zero and sine-sweep tools.

03

Body & torso · Damiao DM

The torso pitch joint runs the same Damiao/CAN stack as the arms — shared driver, shared GUI status and quick-control.

04

Hands · Feetech

16× HLS3915 finger servos (IDs 1–16) + 1× HLS3930 wrist (ID 17) on a 1 MHz TTL chain. ID assignment and register config done in our own setup scripts + GUI; USB adapter auto-detected.

05

Neck · Dynamixel

3-DOF neck (yaw / pitch / roll) driven through our dynamixel_neck library — pan-tilt-roll without the Wizard.

06

Lift · RP2040 Pico

MicroPython on a Pico: BTS7960 H-bridge + quadrature encoder, cascaded position + velocity control on-board, a host serial library and an iOS GUI (position / velocity / calibration).

Flash it. Tune it. Drive it.
