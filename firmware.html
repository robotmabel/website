Overview / Software / Firmware
L1 · Firmware

Close to the metal.

Each actuated subsystem runs its own microcontroller firmware — deterministic loops down at the bus level, with a clean command/feedback contract up to ROS. Torque goes down, encoder and current come back.

Teensy · PlatformIOCAN FD / RS-485REV CAN protocolDynamixel / Feetech
Per-subsystem

One MCU per limb.

Firmware lives in firmware/, one target per actuated subsystem — so a single board can be flashed, debugged, or swapped without disturbing the rest of the robot.

01
Swerve base

Teensy firmware (PlatformIO) drives the three swerve modules over the REV CAN protocol — six brushless motors, drive plus steer. Ships with a Python GUI and a drive sim; setup_can.sh brings up and enumerates the bus.

02
Arms

PlatformIO (C++) firmware runs the OpenArm-derived 7-DOF arms — quasi-direct-drive motors on CAN FD, fast enough for gravity compensation and impedance control.

03
ORCA hands

The 17-DOF tendon-driven ORCA hands run on Dynamixel / Feetech servos through the orca_core driver, exposing per-joint position feedback to the host.

04
Head & lift

A 3-DOF Dynamixel neck (pan / tilt / roll) is driven from the Dynamixel SDK; the linear lift column runs its own MCU firmware with a host-side GUI for setup and homing.

Buses & I/O

Talking to every joint.

Dozens of actuators, one real-time edge. Here's how the bytes move below the line.

01
Real-time actuator bus

Quasi-direct-drive motors run on CAN FD; swerve and wrists ride RS-485. Torque goes down, encoder and current come back — 200 Hz+, fast enough for gravity comp and impedance.

02
Deterministic loop

C++ firmware on the microcontrollers holds the hard real-time edge; the Jetson closes the outer control loop at a fixed rate above it. See Hardware for the wiring.

03
CAN bus bring-up

For the swerve base, setup_can.sh then can_up.sh / can_scan.sh enable and enumerate every CAN device before the driver ever publishes a command.

04
Clean contract to ROS

Every firmware target exposes the same shape — joint command in, joint state out — so the matching ROS driver wraps it behind standard topics with no special cases.

Targets

Five boards, one repo.

01

swerve_drive

Teensy + PlatformIO over the REV CAN protocol, with a Python GUI and a drive sim for the 3-module base.

02

openarm

PlatformIO (C++) motor control for the 7-DOF arms — quasi-direct-drive on CAN FD.

03

orca_hand

17-DOF ORCA hand drivers on Dynamixel / Feetech via the orca_core submodule.

04

head

3-DOF Dynamixel neck (pan / tilt / roll) driven from the Dynamixel SDK.

05

lift

Linear lift-column firmware with a host-side GUI for setup and homing.

06

can tooling

Shared setup_can.sh / can_up.sh / can_scan.sh helpers to bring up and enumerate the bus.
