00Overview

Everything needed to build, wire, flash, and operate a MABEL — an open-source mobile bimanual robot. This is the replication manual: parts, steps, commands, and checks, in build order. The project site covers what the robot can do; this covers how to make one.

Before you order anything

Three gaps in the parts list will stop a build if you meet them at the bench instead of here. All three are tracked in BOM/data/open_items.csv.

GapWhat it means for your order
The swerve line is a lumpREV-21-3005 is the MODULE only — motors, controllers and framing are not included. Each module also needs a NEO, a NEO 550, a SPARK Flex and a SPARK MAX, about $557 more per module. Ordering the BOM line as written gets you three modules that cannot move.
Two Teensy 4.1 are missingOne drives the swerve base, one drives both arms. Neither appears in the parts list; without them the robot has no low-level control at all.
No hardware E-stop is costedThe safety docs describe a hardware stop that de-energises the actuators independently of the host, and the software E-stop (hw.estop()) is not that. Budget $30–80 for a switch and contactor — the OpenArm harness set may already include one, unconfirmed.

The rest of the fixed core can be ordered on day one: none of it depends on a decision made later. The five deferred choices (compute, head camera, wrist cameras, base depth camera, lidar) are laid out in 01 · BOM.

You can do everything up to real hardware on a laptop alone. Build the simulation stack first (05 · Software), drive the digital twin, and only then order parts — every motion you'll ever command can be proven in the twin before a single motor exists.

Build order

  1. 01 · Bill of materials. Pick a tier, order everything, start the printer.
  2. 02 · Mechanical assembly. Base → lift → body → arms → hands → head. Each module is built and checked before the next stacks on.
  3. 03 · Electronics & wiring. Land the PCBs, run the CAN/TTL/USB buses, connect sensing, power from one pack.
  4. 04 · Firmware. Flash the base Teensy, arms Teensy, lift Pico; assign every servo ID.
  5. 05 · Software. Sim stack on the laptop; ROS 2 workspace + hardware layer on the Jetson.
  6. 06 · Bring-up & calibration. First power-on limp, bus-by-bus enumeration, zeros, limits, CoM check.
  7. 07 · Operate. Teleop from a browser, iPhone, or Vision Pro; the terminal cockpit; the safety model.
  8. 08 · Data & learning. Record episodes, curate, train, deploy policies.

The golden rules

  • Simulate first. Prove every motion in the twin before running it on hardware.
  • One source of truth. The MuJoCo MJCF defines the body; the URDF, viewers, and app rigs are all generated from it.
  • Power up current-limited, always. First energization of any bus goes through a current-limited supply.
  • Know your stop. Identify the e-stop path before energizing anything (safety model).
