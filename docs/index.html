        materials, printed parts, wiring, PCBs, firmware, ROS, simulation,
        calibration, teleoperation, learning, and the bugs that will bite you

        written by more than one of us. Every chapter takes pull requests;

How to put something here

    

      

        
One file. One pull request. No account.

        
Everything on the shelf is an object in
          website/docs/data/community.json. Add yours, open a PR,
          and it appears. Nothing else needs touching — no build step, no
          CMS, no invitation.

        
{
  "kind":  "build",          // build | scene | skill | part | tool
  "title": "MABEL #7, Lisbon",
  "who":   "your name or handle",
  "url":   "https://...",    // repo, thread, video, anything
  "shot":  "https://...",    // optional image
  "stage": "wiring",         // planning | printing | wiring | running | shipped
  "blurb": "One or two sentences. What is it, what is different about it.",
  "tags":  ["hardware", "swerve"]
}

        
Builds in progress are welcome and wanted. A half-wired
          chassis with a note saying which step was wrong is more useful to the
          next person than a finished photograph.

      

      

        
Fixing the manual counts too

        
If a step was wrong, a part was missing, or a command did not run,
          that is the highest-value contribution there is — every chapter has
          an Edit this page link at the foot that opens the file on GitHub.

        
    
          
  • A wrong torque, a missing washer, a bolt length that does not fit
    • 
          
  • A command that needs a flag on your distro
    • 
          
  • A part that is out of stock, with the substitute that worked
    • 
          
  • A photograph of the step you got stuck on
