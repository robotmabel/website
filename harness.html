Overview / AI harness
The AI harness

The repo answers
for itself.

MABEL is 40-odd subsystems, five buses, three simulators and nine studios. Ask an assistant about any of it and you get a confident answer assembled from whatever it happened to read. So the repo ships a harness: 25 commands over a registry where every fact names the file it came from, and a gate that fails when that file stops saying it.

What a harness is

Most failures aren’t
reasoning failures.

A harness is the structured environment around an agent — how it reaches tools, what state it can see, and how it checks that a step worked. When an assistant gets a robot wrong it is rarely because it reasoned badly. It is because nobody gave it a way to look, and nothing told it that its answer had gone stale. This is the framing HARBOR makes for robot RL; MABEL applies it to the repository itself.

01

One registry

Nine YAML files hold every fact about the robot — hosts, ports, control paths, safety limits, the firmware buses, the controller API. Nothing is remembered; everything is read.

02

One namespace

Every command is /mabel-<verb>. They used to be bare words — /status, /network, /control — which read as global claims and named no robot.

03

One gate

Every fact cites a file. /mabel-drift checks each of those files still exists and still says it. A drift failure is a failing test, not a warning.

The registry

Every answer
cites a file.

The commands are thin. They render a registry, and the registry is the artefact — nine files under claude_harness/data/, each entry carrying the path it was read from. That citation is what makes the gate possible: a fact with no source cannot be checked, so the harness does not accept one.

FileHolds
commands.yamlThe command surface — this page is generated from it
hosts.yamlthor, the relay VPS, the dev Mac — addresses, roles, access paths
network.yaml42 ports, their protocols, and the browser’s route through Caddy and rathole
control.yamlAll 11 ways to drive the robot, the 8 launch targets, the 9 studios
safety.yamlE-stop, watchdogs, motion limits, arbitration — each citing its implementation
firmware.yamlPer-subsystem MCU, bus, protocol and the build/flash commands
controller_api.yamlThe mabel control library’s public surface, by subpackage
hardware_api.yamlThe mabel_hw HAL by area — drivers, RPC, cameras, config switches
subsystems.yamlWhat every top-level directory is, and how data moves between them
docs.yaml · glossary.yamlThe 40 technical papers; the vocabulary that means something specific here
Gates

A check that fails
is worth more than
a doc that doesn’t.

Documentation rots silently; that is its defining property. The harness answers that with executable checks — and with an honest account of what each one does and does not catch, because a gate believed to cover more than it does is worse than no gate.

GateWhat it catches
citationA registry fact whose file was deleted, moved, or no longer contains it. 181 facts, checked on every run.
surface →A command this page advertises that has no definition in the repo.
surface ←A command shipped in the repo that this page never mentions — which is how a harness gets a reputation for being smaller than it is.
viewA command pointing at an engine view that was renamed, caught here rather than when someone types it.
papersA subsystem whose docs/*.tex has gone missing. 40 of 40 present.
safety sourcesA safety mechanism citing a file that no longer implements it.
And what it does not catch. drift is a citation checker, not an architecture checker. It verifies that every cited fact still exists — and it passed clean through the whole neck migration while the invariant it documents was being violated. Architectural invariants are enforced by tests instead (hardware_bridge/tests/), so a new rule goes there, not here. Saying so is part of the gate: one believed to cover more than it does is worse than none.

What the badges mean

Deliberately absent

What it won’t do.

A missing capability nobody wrote down reads as an oversight. These are choices, and they are in the registry next to the commands so that /mabel-help prints them in the same breath.

    Use it

    Clone it, open it,
    ask it.

    The harness lives in the repository, so it arrives with the clone. Open the repo in an assistant that reads .claude/commands/ and the 25 commands are there. Or type nothing at all and ask in plain language — “how do I drive the base?”, “what’s on port 9090?”, “why won’t this motor answer?” — and it reaches the same registry.

    First

    /mabel-onboard

    Ten minutes to legible: what the robot is, the map, the hosts, the one wire contract, and the two rules that never bend.

    Then

    /mabel-safety

    Before you drive anything. Every base twist from every input device passes one function, and nothing routes around it.

    Any time

    /mabel-help

    The whole surface, including the part that says what it will not do.
